Professional overview

I focus on translating manual administrative workflows into structured digital systems. The projects in this portfolio cover employee records, appointment booking, cafe ordering, travel management, organisation membership, and IT inventory — each one starting from how the work is actually done rather than from a template.

Across those projects I work through requirements analysis, interface development, database design, role-based workflows, validation, testing, and technical documentation. Most of what I build has more than one kind of user, so access control and clear role separation tend to shape the architecture early.

IT technical support

I support users, workstations, printers, software, connectivity, Microsoft 365, and IT assets day to day: desktop and laptop troubleshooting, Windows workstation support, software installation and configuration, printer setup, network and Wi-Fi connectivity checks, device deployment, and equipment inventory with QR and barcode asset workflows.

That side of the work led directly to the Mobile IT Inventory Scanner — manual asset lists are slow to maintain and hard to audit, and the workflow was worth rebuilding properly.

Full-stack development

My main stack is PHP and Laravel with MySQL behind responsive HTML, CSS, JavaScript, and Bootstrap interfaces. I have also worked with C# and ASP.NET Core alongside SQL Server. Where a system needs a public, dependency-free demonstration, I build a browser-based version using LocalStorage so the workflow can be tested without a server — which is how the BookEase PH, Codexa Cafe Kiosk, and IT inventory demos in this portfolio work.

Two of my larger systems — PTC WorkWise and LakbayGo — were built for Pateros Technological College and a travel-booking scenario respectively. Their source is not public, so this portfolio presents their captured interfaces and documented architecture rather than a deployment I cannot honestly link to.

Work approach

Workflow first

I map who does what, and in what order, before deciding on screens or schema.

Role-aware by default

Multi-role access control is planned at the start, not retrofitted at the end.

Documented as built

ERDs, flowcharts, and written architecture accompany the code, not trail it.

Honest about status

A demo is labelled a demo. If something is not deployed, I say so plainly.

How I work

  1. 01

    Discovery

    Clarify the users, the workflow, the constraints, and the actual problem to solve.

  2. 02

    Planning

    Define roles, modules, data relationships, and an achievable delivery sequence.

  3. 03

    Interface & data design

    Map screens, validation rules, user flows, and the database relationships behind them.

  4. 04

    Development & testing

    Build the modules, then verify behaviour, accessibility, and responsive layout.

  5. 05

    Deployment & improvement

    Prepare the release, document the system, and refine it from real feedback.
